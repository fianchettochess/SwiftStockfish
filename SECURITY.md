# Security Policy

## Supported versions

Security fixes target the latest tagged release and the `main` branch. Older
releases may not receive patches.

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use GitHub's
private vulnerability reporting form in this repository's **Security** tab. If
that form is unavailable, contact a maintainer through GitHub without including
sensitive details so a private reporting channel can be arranged.

Reports involving untrusted UCI input, NNUE filename or download handling,
checksum verification, filesystem access, process termination, hangs, or
excessive resource use are especially useful. Include the affected version, a
minimal reproducer, impact, and any suggested mitigation when possible.

Before sharing diagnostics, remove credentials, tokens, session URLs, local
network addresses, hostnames, and filesystem paths. Non-sensitive defects can
use the public issue tracker.
